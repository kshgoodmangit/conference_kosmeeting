# 사용자 비밀번호 재설정

## 적용 순서

1. MariaDB 10.6에서 `document/member_password_reset_migration.sql`을 1회 실행합니다. 운영 DB에 자동 적용하지 않습니다.
2. 아래 설정과 기존 Gmail SMTP 설정을 확인합니다.
3. 애플리케이션을 배포하거나 재시작합니다. `/forgot-password`에서 요청하고 이메일의 링크로 새 비밀번호를 설정합니다.

```yaml
app:
  member-password-reset:
    enabled: ${MEMBER_PASSWORD_RESET_ENABLED:true}
    public-base-url: ${MEMBER_PASSWORD_RESET_PUBLIC_BASE_URL:http://localhost:8080}
    token-ttl: 30m
```

- 로컬 주소는 `http://localhost:8080`입니다. 운영에서는 `MEMBER_PASSWORD_RESET_PUBLIC_BASE_URL`을 실제 사용자 사이트의 HTTPS 주소로 지정합니다. 이메일을 읽는 기기에서 접속 가능한 주소여야 합니다.
- 외부 사이트 주소는 HTTPS만 허용합니다. HTTP는 localhost 및 127.0.0.1에만 허용합니다. 요청의 Host나 전달 헤더로 링크를 생성하지 않습니다.
- Gmail 연결은 `app.maintenance-request.mail`의 활성화·서버·포트·계정·비밀번호·발신 주소와 기존 `maintenanceMailSender`를 재사용합니다. SMTP 계정/비밀번호는 복제하거나 응답에 포함하지 않습니다.
- 메일 발신 표시명과 제목은 해당 학회명으로 구성합니다. 유지보수 알림 메일의 제목·본문은 변경하지 않습니다.
- 비활성화, 누락된 SMTP 설정, 잘못된 사이트 주소, DB 미적용 또는 작업 큐 포화 시 일반화된 503 오류를 반환합니다. SMTP 접속·인증·배달 실패는 비동기 발송 로그로 확인합니다.

## API와 화면

모든 API는 JSON POST이고 기존 Spring Security CSRF 검증을 적용합니다. HTML 폼의 CSRF 토큰을 `X-CSRF-TOKEN`으로 전달합니다.

| 경로 | 본문 | 정상 응답 |
| --- | --- | --- |
| `/api/public/members/password-reset/request` | `email` | 202, 가입 여부를 드러내지 않는 공통 안내 |
| `/api/public/members/password-reset/validate` | `token` | 204, 링크 유효 |
| `/api/public/members/password-reset/confirm` | `token`, `password`, `passwordConfirm` | 204, 변경 완료 |

- 메일 요청과 회원 조회는 분리합니다. DB 요청 제한을 거친 뒤 회원 조회·메일 전송은 2개 작업 스레드, 최대 대기 100건인 큐에서 수행합니다.
- 가입하지 않은 주소와 발송 제한에 걸린 주소도 동일한 202 안내를 반환합니다. 응답은 메일 전송 완료를 의미하지 않습니다.
- 요청 제한은 UTC 고정 시간 구간 기준으로 이메일당 분당 1회·시간당 5회, IP당 시간당 30회입니다. 검증·변경 시도는 합산 IP당 시간당 60회이고 초과하면 429를 반환합니다.
- IP는 기존 `ClientIpResolver`의 신뢰 프록시 설정을 적용합니다. 프록시 배포 시 `app.admin-ip-access.trusted-proxies`를 정확히 설정해야 합니다.
- 요청 제한 키는 개인정보 암호화 설정 키를 이용한 HMAC-SHA256으로 저장합니다. 이메일 및 IP 원문은 제한 테이블에 저장하지 않습니다.
- 메일 링크는 `/reset-password#token=...` 형식입니다. 새로고침 시 같은 토큰을 다시 검증할 수 있도록 비밀번호 변경에 성공할 때까지 주소의 프래그먼트(`#token=...`)를 유지합니다. 토큰은 페이지 조회 URL의 쿼리 문자열이나 별도 브라우저 저장소에 저장하지 않으며, 변경 성공 후 주소에서 제거합니다.
- 유효한 링크는 재설정 화면을 새로고침해도 계속 사용할 수 있습니다. 새로고침은 토큰 유효시간을 연장하지 않습니다. 잘못되거나 만료·사용된 링크는 재발급 화면으로 안내합니다.
- 회원가입·마이페이지 비밀번호 변경·비밀번호 재설정의 새 비밀번호는 모두 8~16자로 제한합니다. 로그인 코드가 앞뒤 공백을 제거하므로 변경·재설정 시에는 앞뒤 공백을 허용하지 않습니다. 회원정보 수정에서는 비밀번호를 변경할 수 없으며 `/mypage/password` 전용 화면을 사용합니다.

## 토큰·세션·트랜잭션

- 토큰은 SecureRandom 32바이트이고 DB에는 SHA-256 해시만 저장합니다. 기본 유효시간은 30분, 설정 가능한 최대 유효시간은 1시간입니다.
- 토큰은 발급 시점의 학회·회원·비밀번호 상태와 연결됩니다. 다른 학회나 변경된 비밀번호 상태의 링크는 사용할 수 없습니다.
- 비밀번호 저장과 해당 회원의 모든 링크 사용 처리는 하나의 트랜잭션입니다. 회원 행을 먼저 잠가 동시에 두 링크가 사용돼도 한 요청만 성공하도록 처리합니다.
- 단순 메일 요청이나 링크 열기는 비밀번호를 바꾸지 않습니다. SMTP 실패 시 새로 발급한 토큰을 폐기합니다. 종전 링크는 새 링크 요청만으로 취소하지 않습니다.
- 로그인 시 비밀번호 해시의 지문을 세션에 저장하고, 이후 요청에서 DB의 현재 지문과 비교합니다. 비밀번호 변경 후 종전 회원 로그인은 다음 요청에서 해제됩니다. 같은 세션의 관리자 로그인 정보는 유지합니다.
- **배포 전에 생성된 회원 세션에는 지문이 없으므로 배포 후 한 번 다시 로그인해야 합니다.** 이미 처리 중인 요청을 소급 취소하지는 않습니다.
- 초기 SQL은 테이블만 생성하며 기존 회원 정보와 비밀번호를 변경하지 않습니다. 만료 후 하루가 지난 토큰 및 하루가 지난 제한 기록은 매시간 정리합니다.
- 토큰·메일 링크·비밀번호·SMTP 예외 상세는 로그에 기록하지 않습니다. 실패 로그에는 학회 식별자와 오류 유형만 기록합니다.

## 운영 확인

- SQL 적용과 운영 URL 설정 후 실제 수신 가능한 테스트 계정으로 메일 수신, 만료, 재사용 차단, 기존 비밀번호 로그인 실패, 새 비밀번호 로그인 성공을 확인합니다.
- 자동 테스트에서는 SMTP를 모의 처리하며 실제 메일을 발송하거나 운영 DB에 쓰지 않습니다.
- 발송 큐는 메모리 기반입니다. 서버가 비정상 종료되면 대기 중 요청이 사라질 수 있으며 사용자는 다시 요청할 수 있습니다. 정상 종료 시 최대 30초 동안 작업 완료를 기다립니다.
