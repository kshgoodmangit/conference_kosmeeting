# 가입 이메일 인증

## 현재 구현 범위

- `/join/international`, `/join/domestic`의 Send code 버튼에서 실제 SMTP 발송을 요청합니다.
- `POST /api/public/members/email-verification/send`에 이메일을 JSON으로 전달합니다. CSRF 토큰이 필요합니다.
- 비밀번호 찾기와 같은 `maintenanceMailSender`를 사용하며, Gmail 접속 정보는 YAML의 `app.maintenance-request.mail` 설정을 그대로 사용합니다.
- 메일은 학회명, 6자리 숫자, 10분 유효기간, 재발송 시 최신 코드 사용, 타인 공유 금지 안내를 포함합니다. 비밀번호 찾기 메일의 Arial 글꼴·600px 폭·파란색 포인트를 따르며 HTML과 일반 텍스트를 함께 보냅니다.
- SMTP 서버가 발송을 수락한 후에만 성공 응답을 반환합니다. 수신함 도착까지 보장하는 응답은 아닙니다.
- 성공 후 인증번호 입력란을 활성화하고 60초 재발송 대기를 표시합니다. 실패 시 입력란은 비활성 상태를 유지합니다.
- 회원 존재 여부는 발송 전에 조회하지 않습니다. 신규·기존 이메일에 같은 발송 동작을 적용합니다.
- Verify는 `POST /api/public/members/email-verification/verify`에 이메일과 코드를 JSON으로 전달합니다. 발송한 브라우저 세션과 CSRF 토큰이 필요합니다.
- 서버가 코드 해시·이메일·학회·유효기간을 확인한 후에만 기존 회원 여부를 조회합니다. 기존 회원이면 로그인·비밀번호 찾기를 안내하고 가입은 허용하지 않습니다.
- 신규 이메일이면 서버 세션에 30분 유효한 인증 결과를 저장하고 Sign Up 버튼을 활성화합니다. 화면에서 이메일을 변경하면 다시 인증해야 합니다.
- 최종 공개 가입 API도 세션의 인증 이메일·학회·만료 시각을 확인합니다. 브라우저 버튼을 조작하거나 가입 API를 직접 호출해도 이 검사를 거칩니다. 성공한 가입은 인증 결과를 소비하며, 폼 오류 등 가입 실패 시에는 남은 유효기간 내에 재시도할 수 있습니다.

## 상태와 발송 제한

- 코드 생성은 SecureRandom을 사용하며, 서버 세션에는 코드 원문 대신 BCrypt 해시·정규화한 이메일·학회 번호·만료 시각을 저장합니다. 응답에는 코드를 포함하지 않습니다.
- 한 브라우저 세션은 최신 발송 건 하나만 보관합니다. 새 발송 시 이전 코드와 인증 결과를 제거하고, SMTP 실패 시 신규 코드를 저장하지 않습니다. 검증 성공 시 사용한 코드를 제거하여 재사용을 막습니다.
- 코드를 5회 틀리면 해당 코드는 폐기합니다. 검증 요청은 IP별 1시간에 60회까지 허용합니다.
- 세션 만료/서버 재시작 시 코드를 다시 요청해야 합니다. 세션 내 검증·가입 처리는 동일 서버에서 직렬화합니다. 여러 서버 운영 시 같은 세션 요청이 같은 서버로 가도록 고정 라우팅이 필요하며, 서버 간 동시 세션 처리는 별도 분산 잠금 설계가 필요합니다.
- 이메일별 60초에 1회, 학회별 동일 이메일에 1시간에 5회, IP별 1시간에 30회 발송 시도를 허용합니다. 허용된 시도의 SMTP 실패도 횟수에 포함합니다.
- 제한은 DB에서 원자적으로 갱신하므로 세션을 새로 만들거나 서버가 여러 대여도 공유됩니다. 이메일과 IP는 용도를 포함한 HMAC 값으로 저장합니다.
- 시간 구간은 해당 대상의 최초 요청부터 시작하며, 만료 후 다음 요청에서 초기화합니다. 오래된 제한 기록은 매시간 정리합니다.
- SMTP 예외 내용, 이메일 주소, 인증번호는 로그에 기록하지 않습니다.

## 적용 순서

1. 대상 DB를 백업하고 `document/member_email_verification_migration.sql`을 1회 실행합니다. 개발/운영 DB에 각각 적용해야 합니다.
2. 기존 Gmail SMTP 설정이 활성화되어 있고 비밀번호 환경변수가 실행 프로세스에 전달되는지 확인합니다. 기존 비밀번호 찾기 발송 설정을 공유합니다.
3. 변경된 애플리케이션을 빌드하고 재시작합니다. 정적 JavaScript도 함께 반영합니다.
4. 수신 가능한 본인 이메일로 Send code를 눌러 제목, 인증번호, 유효기간, 스팸함을 확인합니다.
5. 코드를 입력하고 Verify를 누릅니다. 신규 이메일은 인증 완료와 가입 활성화, 기존 이메일은 로그인·비밀번호 찾기 안내를 확인합니다.

기존 발송 기능을 위해 위 마이그레이션을 이미 적용했다면 Verify 기능에 추가 SQL은 필요하지 않습니다. 백엔드 재시작 후 페이지를 새로고침하고 새 코드를 요청합니다.

작업 중 실제 Gmail 수신자에게 테스트 메일을 발송하거나 대상 DB에 DDL을 실행하지 않았습니다.
서비스·컨트롤러·MIME 내용은 모의 SMTP 테스트로, 화면 상태 전이는 Node 테스트로 검증합니다.
