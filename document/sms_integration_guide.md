# 문자발송 메뉴 및 업체 연동 안내

## 적용

- 경로: `/admin/sms`, 메뉴 키: `sms`.
- 메일 주소록이 이미 설치된 환경에서는 그 주소록의 `phoneNumber`를 사용한다. 주소록 원본이 삭제되면 작성 중인 문자의 해당 조건을 제거해야 한다. 이미 준비된 명단은 원본과 독립적이다.

## 현재 기능

- 문자 작성·수정·삭제, 제목/내용/발신번호 및 상태 검색, 서버 집계 통계, 페이지 이동.
- 제목(최대 100자), 본문(최대 2,000 UTF-16 코드 단위), 발신번호, AUTO/SMS/LMS 요청 유형, 발송 희망 일시 저장.
- 회원 전체·사전등록자 전체·초록 접수자 전체·초록 채택자 전체와 주소록·회원 검색·개별 번호 선택.
- 메일과 그룹 조회 조건 및 그룹 선택 UI를 공통 사용한다. 사전등록 취소·초록 임시저장 제외, 채택은 approved이며 접수 회원 기준이다.
- 모달을 열 때만 그룹 인원을 조회한다. 선택 변경 시 서버 조회하지 않고 단순 합계를 표시한다. 그룹 인원은 유효 번호와 문자 채널 수신 거부를 반영하며 합계에는 소스 간 중복이 포함될 수 있다.
- 준비 시 최신 데이터를 다시 조회해 번호별 중복 제거와 번호 오류·문자 수신 거부를 반영하고 명단을 고정한다. 준비 이후 수정·삭제는 거부한다.
- 준비 상세에서 대상/제외/중복 통계와 확정 명단을 페이지별 조회한다.
- 목록 통계는 현재 검색어와 상태에 일치하는 전체 결과의 totalCount/draftCount/preparedCount다.

## 번호 및 수신 거부

국내 휴대폰은 `010…`, `+82…`, `0082…` 형식을 같은 `+82…` 번호로 정규화한다. 해외 번호는 `+국가번호`를 포함해야 한다. 이는 형식 검사이며 실제 가입·수신 가능 여부의 확인은 아니다.
발신번호는 8~11자리 숫자를 허용하지만 발신번호 소유권·업체 등록 여부는 아직 확인하지 않는다.
문자 수신 거부는 `sms_suppression_list`에 정규화 번호로 저장한다. 메일 수신 거부와 혼용하지 않는다. 이 단계에는 수신 거부 등록 UI 또는 공개 콜백을 제공하지 않으며 실제 업체 연동 시 문자 전용 수신 거부 이벤트를 연결해야 한다.

## 실제 발송은 비활성화

캠페인과 작업 상태 PREPARED, 수신자 READY는 **미발송**이다. 네트워크 전송, 자동 발송 작업, 예약 스케줄러, 발송 API는 없다. 희망 일시는 저장 정보일 뿐이다. 준비 요청은 캠페인을 FOR UPDATE로 잠그며 같은 키 재요청은 기존 작업을 반환한다. DB의 캠페인별 작업·요청 키·번호별 스냅샷 유일 제약도 적용한다.

`SmsGatewayProperties`의 기본값은 `enabled=false`, `provider=none`이다. 환경 설정은 다음과 같다.

```yaml
app:
  sms:
    enabled: false
    provider: none
```

## 업체 추가 시

1. `sms/{provider}/`에 업체별 설정 바인딩과 `SmsGatewayAdapter` 구현 Bean을 추가한다. 키/토큰/Secret은 환경변수나 외부 설정으로 주입하며 프론트엔드에 전달하지 않는다.
2. `SmsGatewayRegistry`가 어댑터를 수집한다. 활성화 여부와 선택 업체를 확인한 뒤에만 사용할 수 있다. 준비 서비스는 이 어댑터를 호출하지 않는다.
3. 업체의 문자 인코딩·바이트 계산·SMS/LMS 한도·발신번호 등록·지원 국가·광고/수신거부 안내 요건을 검증한다. 현재 2,000자 입력 한도를 업체의 발송 가능 길이로 해석하지 않는다.
4. 별도로 승인된 실제 발송 기능과 작업자를 구현한다. 기존 PREPARED 작업을 배포 직후 자동으로 발송하지 않는다. 명시적인 발송 승인·예약 활성화 후에만 QUEUED로 옮긴다.
5. 작업자가 수신자 단위로 점유하고 안정적인 중복 방지 키를 `Dispatch.idempotencyKey`로 전달한다. 타임아웃은 실패로 단정하여 무조건 재전송하지 않고 업체 접수 상태를 조회한다.
6. `send()`의 Receipt는 업체 접수일 뿐 최종 도착이 아니다. 검증된 콜백/조회로 SENT/DELIVERED/FAILED 상태와 providerMessageId/errorMessage를 기록하고 재시도 정책·관측 지표를 추가한다.
7. 콜백은 서명·인증과 중복 이벤트 처리를 검증한다. 실제 발송 직전에도 최신 문자 수신 거부를 적용한다. 필요한 광고 구분과 수신 거부 안내는 업체 연동 범위에서 구현한다.
8. 예약 시각은 현재 애플리케이션 로컬 시각으로 저장한다. 업체 연동 시 기준 시간대(Asia/Seoul 등)를 명시하고 전송 전에 변환한다.
