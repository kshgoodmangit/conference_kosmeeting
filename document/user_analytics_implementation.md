# 사용자 접속 분석 구현

## 화면 및 API

- `/admin/dashboard/user-analytics`: 기존 세계지도 현황판. 최근 30일 요약·국가·추이·실시간·유입경로. 60초 자동 조회.
- `/admin/dashboard/user-analytics-details`: 기간 조회(기본 30일, 최대 90일), 전체 기기·브라우저·OS·국가·유입경로, 7요일 × 24시간 히트맵, 인기 페이지, 일별 추이. 메뉴는 기존 현황판과 함께 프론트엔드에서 연결한다.
- 기존 테스트 데이터 화면: `60일 접속 데이터 생성` 버튼. 선택 학회에 생성하며 공통 확인창, 비동기 진행률, 완료 요약 제공.
- `GET /api/analytics/config`: 공개 수집용 세션 CSRF 토큰.
- `POST /api/analytics/events`: 공개 사용자 화면 이벤트 수집. CSRF 유지, cross-site 차단, IP별 분당 600건 제한. 요청 본문은 `AnalyticsCollector.Event` 참고.
- `GET /api/admin/analytics?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`: 관리자 세션·권한과 `X-Conference-Seq` 필요.
- `GET /api/admin/analytics/dashboard`: 현황판 전용 경량 조회. 동일한 기간 파라미터·학회 헤더를 사용하며 전체 기간 `mapCountries`를 포함한다. 상세 통계 API와 기존 `includeMapCountries=true` 계약은 유지한다.
- `POST /api/admin/testdata/analytics`, `GET /api/admin/testdata/analytics`: 관리자 전용 생성 시작·상태 조회.

## 스키마

기존 3개 테이블에 `document/analytics_read_model_migration.sql`의 `analytics_daily_facts`와 일별 요약의 `sourceMaxEventSeq`, `aggregationVersion`을 추가한다. 사용자가 스키마를 적용했다. 아래 원본 인덱스는 앞서 안내한 보완 인덱스다.

```sql
ALTER TABLE analytics_events
  ADD INDEX idx_analytics_conference_type_date
    (conferenceSeq, eventType, isBot, occurredAt);
```

기존 인덱스에서 `conferenceSeq`만 탐색 키로 선택하고 날짜를 index condition으로 검사하는 실행 계획을 확인했다. 새 인덱스는 PAGE_VIEW/비봇 조건을 앞에서 적용하기 위한 것이다. 실제 개선 폭은 적용 후 다시 측정해야 한다. 원본 DISTINCT·종료 판정을 여러 번 조회하므로 대량 데이터의 최초 조회에는 시간이 걸릴 수 있다.

`dimensionType`은 기존 COUNTRY/DEVICE/SOURCE/PAGE/HOUR에 BROWSER/OS 값을 함께 사용한다. 현재 VARCHAR(20)이므로 ALTER 없이 저장 가능하다.

원본 이벤트는 보존한다. 10초 간격의 백그라운드 작업이 변경된 학회·날짜만 처리한다. facts·일별 요약·차원·워터마크를 날짜 단위 트랜잭션으로 교체하고 실패하면 재시도한다. 시작 시 누락·이전 버전·미반영 날짜를 찾아 복구한다. 최초 복구 중인 학회에는 503 및 Retry-After를 반환해 불완전한 수치를 표시하지 않는다.

일반 조회는 원본 대신 facts의 기간 내 DISTINCT를 사용하므로 여러 날의 순 방문자·세션을 잘못 합산하지 않는다. 일별 추이는 daily_summary, 시간대는 daily_dimensions를 사용한다. 전체 기간 지도 역시 해당 학회의 facts를 조회한다. 실시간만 원본의 최근 5분/직전 5분을 조회한다. 조회 요청에서 재집계를 실행하지 않는다.

오늘은 5분마다 종료 판정을 갱신한다. 어제는 다음 날 서울 시간 00:30 이후 첫 실행에서 최종 갱신하고 반복 대상에서 제외한다. `daily_summary.updatedAt`에 집계 시작 시각을 명시적으로 기록하므로 값이 같아도 완료 여부가 남고, 00:30을 가로지르는 작업은 성급하게 확정하지 않는다. 실패 시 재시도하며, 시작 시에도 미확정 과거 날짜를 찾아 장기간 중단 후 복구한다. 별도 DB 컬럼은 필요 없다.

새 이벤트가 없으면 facts를 다시 만들지 않는다. 수집 알림은 확정된 날짜라도 강제 갱신해 지연 커밋을 반영한다. 자정~00:30에 들어온 어제 이벤트를 반영한 후에도 최종 갱신 대상으로 남긴다. 기본 조회 결과는 학회·기간·조회 종류별로 캐시하고, 집계 완료 시 삭제 대신 갱신 대상으로 표시한다. 120초 기본 갱신, 집계 변경 시 최소 30초 간격 갱신, 최대 300초 스냅샷 사용 제한을 적용한다. 상세 정책은 아래 첫 로딩 개선 항목을 따른다. 화면은 60초마다 조회하며 집계는 비동기이므로 즉시 반영을 보장하지 않는다. 원본 보존 기간과 삭제 정책은 별도이며 자동 삭제하지 않는다.

## 수집 범위와 개인정보 최소화

공개 홈페이지는 React SPA가 아닌 Thymeleaf이므로 공통 `public/fragments.html`에 `static/public/js/analytics.js`를 연결했다. `/admin`·`/api`는 수집 대상에서 제외한다.

- 페이지 진입 PAGE_VIEW, 15초 간격 HEARTBEAT, 페이지 종료 PAGE_EXIT.
- 화면이 보이고 최근 60초 이내 입력·스크롤 활동이 있는 시간만 누적한다. 체류시간은 누적 총값이 아닌 증분이며 heartbeat와 exit를 더해도 이중 합산하지 않는다.
- 30분 무활동 시 새 세션. 방문자는 로컬 저장소 UUID(1년), 세션은 탭 세션 저장소 UUID. 저장소 삭제·브라우저/기기 변경은 다른 방문자로 계산된다. 여러 탭은 별도 세션이며 실시간 방문자는 visitor ID로 중복 제거한다.
- 서버 저장은 학회별 HMAC-SHA256 visitor/session 식별값. 원본 IP·UUID·이메일은 저장하지 않는다. HMAC은 기존 DB_ENC_STRING에서 용도를 구분해 사용하므로 해당 키 교체 시 기존 방문자와의 연속성이 달라진다.
- 페이지 경로의 query/hash는 제거한다. 유입 도메인만 저장하며 선택한 UTM 필드는 길이를 제한한다. 사이트 운영자는 페이지 제목·경로·UTM 자체에도 개인정보를 넣지 않아야 한다.
- 브라우저 DNT/GPC 신호를 존중해 수집하지 않는다. 서버는 일반적인 봇 UA를 표시하고 집계에서 제외한다. UA 기반 분류/봇 필터는 추정값이며 완전한 봇 차단은 아니다.
- 공개 화면과 동일한 서버의 최신 학회에 저장한다. 브라우저의 관리자 학회 선택 헤더로 공개 수집 학회를 바꿀 수 없다.
- 관리자 조회·테스트 생성은 기존 관리자 인증·역할·허용 IP·CSRF 구조를 사용한다.

## 통계 정의

모든 날짜·요일·시간 구간은 Asia/Seoul이며 조회 시작일 00:00 이상, 종료일 다음날 00:00 미만이다. 봇은 모든 통계에서 제외한다.

| 지표 | 계산 |
| --- | --- |
| 순 방문자 | 기간 내 PAGE_VIEW의 DISTINCT visitorIdHash |
| 세션 | 기간 내 PAGE_VIEW의 DISTINCT sessionIdHash |
| 페이지뷰 | PAGE_VIEW 이벤트 수(동일 eventId 재전송 제외) |
| 평균 체류시간 | 기간 내 유효 증분 체류시간 합계 ÷ 기간 내 세션 수 |
| 이탈률 | 30분 이상 비활성이고 PAGE_VIEW 1회·체류 10초 미만인 세션 ÷ 전체 세션 |
| 페이지 종료율 | 30분 이상 비활성 세션의 마지막 페이지별 종료 세션 수 ÷ 그 페이지 PAGE_VIEW 수 |
| 국가·기기·브라우저·OS 비중 | 차원별 순 방문자 ÷ 차원별 순 방문자 합계 |
| 유입경로 비중 | 경로별 세션 ÷ 경로별 세션 합계 |
| 실시간 | 최근 5분의 방문자별 마지막 이벤트가 PAGE_EXIT가 아닌 방문자 수. 마지막 페이지에 1번만 배분 |
| 실시간 변화 | 현재 5분과 직전 5분을 같은 방식으로 계산한 차이 |
| 요일·시간대 | 기간 내 PAGE_VIEW를 월~일, 00~23시로 집계 |

한 방문자가 여러 국가/기기로 접속하면 여러 차원에 포함될 수 있다. 따라서 차원별 방문자 합계와 전체 순 방문자는 다를 수 있다. 조회 기간 경계를 가로지르는 세션은 해당 기간 안의 활동을 기준으로 계산하며 기간별 세션 수 역시 단순 합산할 수 없다. 종료/이탈 판정은 즉시 확정하지 않고 30분 비활성 조건을 적용한다.

유입 분류는 UTM social/search 지정을 우선하고, 알려진 검색·소셜 도메인, 일반 외부 링크, 직접 방문 순이다. 전체 브라우저/검색 서비스의 완전한 UA·도메인 사전을 내장한 것은 아니다. 알 수 없는 국가·분류는 UNKNOWN으로 집계한다.

지도는 국가 대표 좌표를 사용하며 개별 IP 위치가 아니다. 국가 순위는 전체 국가 데이터를 표시하고 지도 마커는 등록된 대표 좌표 중 상위 국가만 보여준다. 이동 효과는 해외 → 한국 방향의 설명용 효과다.

## GeoLite2 설정

환경변수 `GEOLITE2_COUNTRY_DATABASE`에 서버에서 읽을 수 있는 MMDB 절대 경로를 지정하거나 `--app.analytics.country-database=...`로 실행한다. MMDB를 Git에 추가하지 않는다.

파일 변경 시 다음 조회에서 최대 60초 간격으로 수정 시각을 확인해 새 reader로 교체한다. 원자적 파일 교체를 권장한다. 경로 미설정·파일 오류·사설/루프백 IP·미매핑 IP는 UNKNOWN으로 처리하고 다른 통계 수집은 유지한다. IP 헤더는 기존 ClientIpResolver의 trusted-proxy 설정만 신뢰한다.

이번 로컬 실행은 사용자가 제공한 `C:/Users/shkim/Downloads/GeoLite2-Country.mmdb`를 실행 인자로 연결했다. 다음 IDE 실행에도 환경변수 또는 실행 인자를 지정해야 한다. 운영 파일 다운로드·라이선스 준수·주기적 업데이트는 운영 환경에서 별도로 관리한다.

## 테스트 데이터

- 서울 시간 기준 오늘 포함 최근 60일. 하루 1,000~2,000건, 총 60,000~120,000건은 PAGE_VIEW 기준이다. HEARTBEAT/PAGE_EXIT 때문에 원본 이벤트 건수는 더 많다.
- 국가·기기·브라우저·OS·유입경로·페이지·시간대·재방문·체류시간·이탈 패턴을 생성한다.
- 실행할 때마다 선택한 conferenceSeq의 원본 이벤트와 집계 테이블 3개의 기존 데이터를 모두 삭제하고 생성한다. 실제/테스트 데이터 구분 없이 삭제하며 다른 행사는 유지한다. 공통 확인창에서 삭제 대상을 알리고, 서버는 confirmedConferenceSeq와 행사 헤더 일치를 검증한다.
- 원격 DB 왕복을 줄이기 위해 500행 단위 multi-row insert, 날짜별 집계. 작업은 백그라운드에서 순차 실행된다.
- 오늘 생성 이벤트도 최소 30분 전 종료되도록 배치해 실제 실시간 접속자와 혼동하지 않는다. 오늘을 포함한 안정적 생성은 01:00 이후 허용한다.
- 서버 재시작 시 메모리 작업 상태는 사라진다. 재실행하면 남아 있는 데이터를 삭제하고 처음부터 생성한다.
- 재생성 중 현황판 조회를 차단하지 않는다. 생성된 날짜까지의 중간 통계가 표시될 수 있다.
- 완료 결과의 `expectedTotals`는 생성한 60일 전체 예상값이다. 방문자/세션은 전체 기간 중복을 제거한다. 동시에 발생한 실제 접속은 예상값에 포함되지 않는다.

## 2026-09-13 실측 검증

### 일반 사용자 접속 통계 화면

- 관리자 대시보드의 `사용자 접속 통계` 메뉴: `/admin/dashboard/user-analytics-details`. 기존 상세 화면을 일반 분석용 화면으로 확장했으며 세계지도 현황판은 그대로 유지한다.

## 첫 로딩 개선 (2026-09-13)

### 구현과 캐시 정책

- 이탈 세션 조회에 기존 `uk_analytics_daily_fact(conferenceSeq,statDate,factKey)` 인덱스를 지정했다. 날짜 범위를 먼저 읽고 기간 내 세션을 GROUP BY한다. DISTINCT, 30분 비활성 조건, 1페이지·10초 미만 기준은 바꾸지 않았다. 일별 방문자·세션의 단순 합산도 하지 않는다. 새 인덱스·DDL·DB 데이터 변경은 없다.
- 현황판은 `/api/admin/analytics/dashboard`로 현재/이전 기간 핵심 지표, 국가, 추이, 유입경로, 실시간, 전체 기간 지도 국가만 요청한다. 캐시가 전혀 없는 경로의 통계 SQL은 16개에서 10개로 줄었다(학회 존재 확인 SELECT 별도). 상세 페이지의 기기·브라우저·OS·시간대·인기 페이지·종료율은 기존 API에 모두 유지한다. 화면 배치와 표시 항목은 유지한다.
- 보고서는 학회·시작일·종료일·현황판/상세 종류별, 지도는 학회별 별도 키로 캐시한다. 각각 최대 100개이며 사용하지 않은 항목부터 제거한다. 계산 중인 항목은 제거하지 않으며 모두 계산 중일 때 새 키를 거부한다. 같은 키의 동시 요청은 하나의 계산을 공유한다.
- 스냅샷 계산 시작 후 120초가 지나면 다음 요청에서 비동기 갱신한다. 일별 집계 커밋 후에는 캐시를 삭제하지 않고 갱신 대상으로 표시하여 계산 시작 후 최소 30초부터 다음 요청이 갱신을 예약한다. 반복 집계가 이 기준 시각을 뒤로 미루지 않는다. 조회 도중 집계가 완료되면 변경 표시를 보존한다.
- 백그라운드 갱신은 보고서·지도 전체에 걸쳐 작업자 1개, 대기열 최대 32개다. SQL을 병렬 분할하지 않는다. 실패·대기열 포화 시 30초 뒤 재시도하며 기존 값을 무기한 연장하지 않는다.
- 스냅샷 계산 시작 후 **300초 이상 지난 값은 반환하지 않는다**. 만료 시 계산 중인 동일 키 작업을 기다리거나 요청 스레드에서 새로 계산한다. 아직 대기열에만 있는 갱신은 요청 스레드가 인계받아 긴 대기열을 기다리지 않으며, 예약 작업이 나중에 실행되어도 중복 계산하지 않는다. 실패하면 오류를 반환하고 재시도 간격을 적용한다. 프론트엔드도 조회 실패 시 이전 수치를 계속 정상 데이터처럼 유지하지 않고 기존 오류 상태와 공통 토스트를 사용한다.
- SQL 실행은 별도 Spring Bean인 `AnalyticsSnapshotReader`의 읽기 전용 REPEATABLE_READ 트랜잭션(60초 제한)에서 수행한다. 요청의 캐시 대기·캐시 적중·학회 검사에는 이 트랜잭션을 열지 않는다. 비동기 갱신도 같은 프록시를 경유한다. 실시간은 요청마다 별도 조회하여 보고서 캐시에 저장하지 않는다.
- 화면은 응답 후 60초 간격으로 조회한다. 따라서 집계 커밋이 화면에 즉시 나타나지는 않는다. 최소 갱신 간격 이후의 요청이 갱신을 시작하고, 완료 후 다음 요청에서 새 값을 받는다. 지연에는 집계 대기·SQL 실행·갱신 대기열·클라이언트 조회 간격이 추가되며, 300초 제한은 이미 만들어진 스냅샷의 사용 한도이다. 원본 수집부터 화면 반영까지 300초를 보장한다는 의미는 아니다.
- 오늘의 5분 종료 판정 갱신, 다음 날 서울 시간 00:30 이후 과거 날짜 확정, 시작 시 미확정 날짜 복구, 지연 이벤트 강제 재집계는 유지한다.

# 현황판 행사 누적 비교 변경 (2026-09-14)

- `/admin/dashboard/user-analytics`와 `/api/admin/analytics/dashboard`는 선택한 `conferenceSeq`의 전체 보관 기간을 기준으로 한다. 현황판 API의 과거 날짜 파라미터는 집계 범위를 제한하지 않는다.
- 순 방문자·세션은 행사 전체 기간의 DISTINCT이며 일별 수치를 더하지 않는다. 페이지뷰·체류시간은 전체 합계, 평균 체류시간은 전체 체류시간 / 전체 세션이다. 이탈률도 행사 전체 기간 세션 기준이다.
- 국가 비중·세계지도는 같은 전체 기간 국가 집계 결과를 공유한다. 유입경로도 전체 기간을 조회한다. 방문 추이는 첫 집계일~마지막 집계일 전체를 표시하고 중간에 기록이 없는 날짜는 0으로 보완한다. 기록이 없으면 날짜는 null, 추이는 빈 배열이다. 실시간 접속만 최근 5분 및 직전 5분 비교를 유지한다.
- 비교 행사는 `conference_settings WHERE seq < 현재 conferenceSeq ORDER BY seq DESC LIMIT 1`로 선택한다. 행사 날짜가 아닌 번호 기준이며, 삭제 등으로 번호가 비어 있어도 직전의 실제 존재하는 행사를 선택한다. 해당 행사에 접속 기록이 없더라도 더 오래된 행사를 대신 선택하지 않는다.
- `previousConference`는 직전 행사의 `conferenceSeq`와 `eventName`, `previous`는 해당 행사의 전체 누적 지표이다. 직전 행사가 없으면 두 필드 모두 null이며 이전 30일 조회는 실행하지 않는다. 비교에 쓰지 않는 이전 행사 이탈 세션도 조회하지 않는다.
- 상단 카드에 직전 행사 대비 증감률을 표시하고 헤더에 비교 행사 번호·이름을 표시한다. 이전 행사 없음 / 이전 행사 통계 없음 / 기준값 0을 구분하며, 기준값 0으로 증감률을 계산하지 않는다. 평균 체류시간 증감률은 표시용 초 단위 반올림 전에 계산한다.
- 일반 상세 통계 `/admin/dashboard/user-analytics-details`의 기간 선택·이전 동기간 비교는 유지한다.
- 성능 테스트를 위해 `AnalyticsService`의 보고서·지도 캐시 우회는 유지했다. 복구용 캐시 호출은 주석으로 남아 있다. 캐시 복구 시에는 현황판 날짜 키를 null로 유지하고 이전 행사 집계 변경 시 이후 행사 현황판도 갱신 대상으로 처리한다.
- 검증: 관련 Java 단위 테스트 17개, TypeScript 전체 검사, 변경 파일 ESLint 통과. 행사 없음·빈 이전 행사·번호 공백·이전 행사 집계 대기·121일 추이·상세 통계 유지·API 계약 및 반복 조회 캐시 우회를 확인했다. 실제 존재하지 않는 이전 행사를 DB에 생성하지 않았다.
- 실행 중인 브라우저에서도 학회 1번의 전체 누적 수치, 비교할 이전 행사 없음, 2026-07-16~2026-09-14 전체 방문 추이와 국가·유입경로 문구를 확인했다. 데스크톱 프레젠테이션 화면을 확인했으며 모바일 크기는 별도로 검증하지 않았다. 서버 재시작·DB 쓰기는 수행하지 않았다.
