이 목록은 원문이 요구하는 기능을 현재 프로젝트와 대조하고 추가 구현 범위를 정하기 위한 기준이다. 이번 단계에서는 원문의 요구사항만 정리했으며, 프로젝트 소스 분석이나 구현 여부 판정은 수행하지 않았다. 아래 모든 항목의 현재 상태는 **미확인**이다. ‘미확인’은 ‘미구현’을 의미하지 않는다.

원문의 요구를 업무 단위로 묶거나 나누어 ID를 부여했다. 한 행에 여러 세부 조건이 있는 경우 모든 조건을 충족해야 해당 행을 ‘구현’으로 판정한다. 시스템 기능, 비기능·운영 요구, 제작·검수 요구를 구분했으며, 원문에 없는 제안은 요구사항에 추가하지 않았다.

## 1 비교 및 판정 방법

| 판정 | 기준 |
|---|---|
| 미확인 | 소스, 설정 또는 동작 증거를 아직 확인하지 않음 |
| 구현 | 해당 요구의 세부 조건과 실제 업무 흐름·산출물이 모두 확인됨 |
| 부분 구현 | 관련 기능은 있으나 일부 조건, 연동 또는 출력물이 부족함 |
| 미구현 | 관련 구현이 없음을 확인함 |
| 외부 연동 필요 | 학회 인증, PG, 발송 서비스 등 외부 시스템과의 연결이 남아 있음. 구현 상태와 함께 기록 가능 |
| 범위 협의 필요 | 원문만으로 정책·대상·검수 기준을 확정할 수 없음. 구현 상태와 함께 기록 가능 |

추후 비교표에는 다음 형식을 사용한다. 메뉴나 화면의 존재만으로 구현 완료를 판단하지 않고, API·DB·권한·예외 처리·실제 산출물까지 확인한다. AGENTS.md의 프로젝트 설명만으로 구현 상태를 판정하지 않는다.

## 17 후속 비교에 사용할 업무 흐름

아래는 원문 요구들을 연결한 검증 시나리오다. 개별 화면뿐 아니라 단계 사이 데이터와 출력물까지 이어지는지 확인한다.

1. **회차 개설**: 과거 회차 복제 → 신규 값 치환 → 이전 값 잔존 점검 → 국영문 콘텐츠·접수·등록 정책 설정 → 검수·오픈.
2. **초록 접수**: 저자·소속 입력 → 본문 정규화 → 동일·유사 제목 검사 → 미리보기 → 접수번호 부여 → 확인메일 → 관리자 조회·수정·통계 반영.
3. **심사와 출판**: 심사위원 배정 → 평가 임시저장·제출 → 집계 → 채택 → 수정 비교·승인 → 프로그램 편성 → 출판용 출력.
4. **발표파일**: 본인 인증 → 필수 동의 확인 → 형식·용량·기간 검증 → 제출·재제출 → 이력·최종본 구분 → 미제출 현황 확인.
5. **유료등록**: 등록·옵션 선택 → 결제 → 옵션 변경 → 차액 결제·부분환불 → 연결 이력 → 최종 영수증 → 통계·정산 대사.
6. **무료등록**: 대상자 업로드 → 초대 → 인증 → 직접 등록·옵션 선택 → 무료 한도 초과분 결제 → 등록 여부 추적.
7. **현장등록 통합**: 현장 최종 내역 입력 → 사전등록 DB 통합 → 본인 내역 조회·증빙 출력 → 통계·정산 반영.
8. **발송**: 시스템 목록·주소록에서 대상 구성 → 중복·제외 처리 → 테스트 → 즉시·예약 발송 → 결과 확인·재발송.
9. **행사 종료**: 회원 인증 기반 자료 검색·열람 전환 → 공개·다운로드 정책 적용 → 백업·보유기간·파기 정책 수행.

## 18 출처 표기 유의사항

- 원문의 `III.2.4`가 ‘프로그램 편성·출판·발표파일’과 ‘시스템 추가 개선 요구’에 중복 사용되어, 후자는 이 문서에서 `III.2 추가 개선 요구`로 표기했다.
- 원문의 장·절 제목을 근거 위치로 사용했다. 페이지 번호는 확인되지 않았으므로 기재하지 않았다.
- 원문의 계약·수행 지시는 요구사항 분석 대상으로만 사용했다. 실제 이관·발송·서비스 변경 작업을 실행한 것은 아니다.
