# 마이페이지 비밀번호 변경

- 마이페이지 홈의 Personal Information 영역에서 `Change Password` 버튼으로 `/mypage/password`에 진입합니다. 회원정보 수정 화면도 같은 페이지로 연결합니다.
- 기존 `mypage` 메뉴를 재사용하므로 관리자 메뉴 등록이나 신규 메뉴 SQL은 필요하지 않습니다.
- 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 입력합니다. 새 비밀번호는 8~16자이며 앞뒤 공백과 현재 비밀번호와 동일한 값은 허용하지 않습니다.
- `POST /api/public/members/password/change`는 JSON으로 `currentPassword`, `newPassword`, `newPasswordConfirm`을 받고 CSRF 토큰을 검증합니다. 회원과 학회는 로그인 세션에서만 결정합니다.
- 성공은 204, 입력 오류는 400과 `{field, message}`, 로그인 만료는 401, 시도 제한은 429, 일시적인 서버 오류는 503으로 응답합니다.
- 학회·회원별 UTC 시간 구간당 최대 5회 변경 시도를 허용합니다. 입력 형식 검증 후 현재 비밀번호를 대조하기 전에 횟수를 차감합니다. 로그인 세션을 새로 만들어도 제한은 유지됩니다. 제한 응답에는 `Retry-After: 3600`이 포함됩니다.
- 회원 행 잠금 안에서 로그인 당시의 비밀번호 지문과 현재 비밀번호를 다시 확인합니다. 비밀번호 저장과 기존 재설정 링크 사용 처리는 같은 트랜잭션입니다.
- 성공하면 현재 회원 인증만 해제하고 `/login?password=changed`로 이동합니다. 다른 기기의 회원 세션은 다음 요청에서 기존 지문 검증으로 해제됩니다. 같은 세션의 관리자 인증 정보는 유지합니다.
- 회원정보 수정 API는 비밀번호를 저장하지 않으며, 기존 비밀번호 변경 파라미터에 값이 있으면 전용 화면 사용을 안내합니다.
- 비밀번호 변경 페이지는 캐시·검색 색인을 제한하고 통계 및 외부 스크립트를 제외합니다. 비밀번호를 URL, 브라우저 저장소, 로그에 기록하지 않습니다.

## 적용 조건

기존 비밀번호 재설정 기능의 `member_password_reset_tokens`, `member_password_reset_limits` 테이블을 재사용합니다. `document/member_password_reset_migration.sql`이 이미 적용된 환경은 추가 SQL이 필요하지 않습니다. 미적용 환경은 기존 재설정 기능의 적용 절차를 먼저 따릅니다. 애플리케이션은 스키마를 자동 변경하지 않습니다.

## 검증

- 서비스: 현재 비밀번호 오류, 길이·공백·확인값 검증, 동일 비밀번호 거부, 변경 시도 제한, 동시 변경으로 만료된 지문, 저장·토큰 무효화의 트랜잭션 처리
- API: 세션 소유권, 미로그인·타 학회·CSRF 차단, 관리자 인증 유지, 필드 오류 및 재시도 안내, 서버 내부 오류 비노출
- 화면: 별도 메뉴 없이 렌더링, 입력 오류와 표시/숨김, 중복 제출 방지, 로그인 이동, CSRF·네트워크 오류 처리
