# 무료 대상자 관리

## 범위

회원 계정과 별개로 학회가 지정한 명단을 관리한다. 개별 등록·조회·수정·삭제, 검색·대상 구분·사용 여부 필터, 페이징, 서버 집계, 정적 XLSX 양식, 행별 부분 성공 일괄등록을 제공한다. 문자·메일 발송, 결제, 무료 한도 적용 및 본인 인증은 포함하지 않는다.

소속, 이름, 직책, 연락처, 이메일, 대상 구분(초청/임원/연자/기타), 사용 여부, 관리자 메모를 저장한다. 이름과 연락처만 필수다. 생년월일은 수집하지 않는다. 명단의 `seq`를 후속 자격·회원 연결의 안정적인 식별자로 사용한다. 현행 `congress_settings` 이력은 회차와 설정 버전이 구분되지 않아 임의로 최신 설정에 연결하지 않는다. 다회차 도입 시 명시적 회차 FK와 `(회차, 이름, 정규화 연락처)` 중복키로 확장한다.

## 메뉴와 보안

- 시스템관리 > 메뉴관리 화면에서 직접 등록했다.
- 상위 메뉴: 회원·등록관리 (`member-registration`). 신규 키: `free-recipients`.
- 관리자 영역, 일반 페이지, `/admin/free-recipients`, 로그인 필요·내비게이션 노출·사용을 선택했다.
- `App.tsx` 지원 메뉴·렌더링 및 `menuIcons.ts`에 연결했다.
- 모든 API는 `/api/admin/free-recipients` 하위이며 기존 관리자 세션·역할 검사 및 CSRF를 적용한다.
- 공통 `DraggableModal`, `useConfirm`, 상위 `onNotify` 토스트와 기존 세션 fetch 처리를 사용한다.
- 다운로드는 개인정보가 없는 빈 정적 양식만 제공한다. 기존 양식 다운로드 패턴에 따라 사유 입력·개인정보 다운로드 감사 대상이 아니다. 실제 명단 엑셀 내보내기는 이번 범위에 없으며 추가 시 공통 사유·감사 서비스를 사용해야 한다.

## 중복 및 검증

- 이름: 앞뒤 공백 제거, 연속 공백 한 칸, Unicode NFC. 영문 대소문자를 구분한다.
- 연락처: 숫자·공백·하이픈·점·괄호·맨 앞 `+`만 허용한다. 구분 문자를 제거하고 국제 접두사 `00`을 제거한다. 한국 국가번호 `82` 뒤 숫자는 앞자리 `0`을 한 번만 붙인다. `010-0000-9001`, `+82 10 0000 9001`, `0082 10 0000 9001`, `+82 (0)10 0000 9001`이 일치한다.
- 원래 연락처와 숫자 대조값을 별도로 저장한다. 입력 30자 이하, 숫자 대조값 8~15자리다.
- 이름+숫자 대조값에 DB 유니크 제약을 적용한다. 사용 여부와 무관하게 중복 검사한다. 이메일만 같은 경우는 중복이 아니다.
- 이메일은 선택값이며 입력 시 주소 형식을 검증하고 소문자로 저장한다.
- 소속 255자, 이름·직책 100자, 이메일 255자, 메모 1,000자. 제어문자는 허용하지 않는다.
- 통계는 검색어·대상 구분·사용 여부를 목록과 동일하게 적용한 전체 결과의 총 건수·사용·미사용 건수다. 한 트랜잭션에서 함께 조회하며 현재 페이지 수를 집계하지 않는다.

## XLSX 일괄등록

- 정적 양식: `frontend/public/templates/free_recipient_bulk_import_template.xlsx`.
- 첫 시트 `무료대상자`: 1행 제목, 2행 안내, 4행 헤더, 5행부터 빈 입력란. 둘째 시트 `작성안내`에 규칙·허구 예시.
- 최대 5MB / 실제 XLSX / 1,000개 데이터 행. 첫 10행에서 헤더 검색. 빈 서식 행은 제외한다.
- 모든 헤더가 필요하며 `*`·공백을 제거하여 매칭한다. 제목·헤더 예시 데이터는 입력 데이터로 처리하지 않는다.
- 파싱을 끝낸 뒤 별도 서비스의 행별 트랜잭션으로 저장한다. 중복은 SKIPPED, 유효성·수식·오류 셀은 FAILED, 정상은 SUCCESS. 행 번호, 이름, 결과 사유와 전체·성공·건너뜀·실패 건수를 반환한다.
- 기존 명단을 덮어쓰지 않는다. 실패 행을 고친 파일을 재업로드하면 이미 성공한 행은 건너뛴다.

### 실제 환경 최종 검증 (2026-09-09)

2026-09-09 관리자 메뉴관리 화면에서 메뉴 생성과 내비게이션 노출을 확인했다. 전용 초기화 코드가 실행된 후 읽기 전용 조회로 `free_recipients` 테이블의 초기 0건을 확인했다.

사용자가 서버를 구동하고 관리자 로그인 및 Chrome 파일 URL 접근 권한을 준비한 뒤 실제 UI 검증을 완료했다. 인증을 우회하지 않았다.

1. 실제 양식에 입력한 `free_recipients_sample_10.xlsx`를 무료 대상자 관리 > 엑셀 일괄등록에 업로드했다. 등록 10명·건너뜀 0명·실패 0명, 5~14행 모두 성공을 확인했다.
2. 목록 총 10명·사용 8명·미사용 2명과 실제 DB 저장값이 일치했다. 샘플 이름·연락처·정규화 연락처·이메일·대상 구분·사용 여부를 XLSX 원본과 프로그램으로 비교해 모두 일치했다.
3. 동일 파일을 다시 업로드하여 등록 0명·건너뜀 10명·실패 0명을 확인했다. 기존 행의 seq는 2~11로 유지되었다.
4. 별도 허구 데이터 `검증임시0909`로 개별 등록·상세 조회·직책 수정·사용 중지·삭제를 확인했다. 잘못된 이메일은 오류 토스트로 거부되고 입력값은 유지되었다. `+82 10-0000-9999`를 `01000009999`로 검색해 조회되는 것도 확인했다.
5. 임시 CRUD 검증 건은 공통 삭제 확인창에서 삭제했으며, 샘플 업로드 전 DB 0건을 확인했다. **샘플 10건(seq 2~11)은 최종 보존했다.** 실제 문자·메일 발송은 하지 않았다.
6. 대상 구분 `초청` + 사용 여부 `미사용` 복합 필터는 샘플무료09 1건·사용 0·미사용 1을 반환했다. 초기화 시 다시 10·8·2가 표시되었다.
7. 데스크톱 및 390×844 좁은 화면의 레이아웃과 라이트·다크모드를 확인했다. 검사 후 원래 화면 크기와 라이트모드로 복원했다.
8. 삭제 성공 문구의 조사 오타를 수정하고 TypeScript 검사와 해당 파일 ESLint를 다시 통과했다. 페이징 경계·행별 부분 실패는 자동 테스트로 검증했으며, 실제 UI 데이터 10건은 한 페이지다.
